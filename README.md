# The Hidden Cost of Vibe Coding: Quantifying Comprehension Debt in LLM-Generated Code

**Journal**: Expert Systems with Applications (SCIE Q1, IF 7.5)

## Overview

This repository contains the complete dataset, code generation scripts, and analysis pipeline for a persona-controlled experiment that quantifies the maintainability costs of *vibe coding*—a development practice in which developers accept LLM-generated code without thorough review.

Two contrasting personas—**Vibecoder** (speed-oriented, minimal documentation) and **Senior Developer** (maintainability-oriented, comprehensive documentation)—were assigned to a single LLM. For 47 LeetCode problems, five repeated generations per persona (470 total code files) were produced and analyzed using multiple static analysis metrics.

### Key Findings

- **Maintainability Index**: Very large effect (Cohen's *d* = −2.504, *p* < .001)
- **Cyclomatic Complexity**: Small effect (*d* = 0.440, *p* = .007)
- **Halstead Effort**: Not statistically significant (*p* = .159)
- **Documentation**: Vibecoder produced 0% docstrings and 0 comment lines vs. 100% for Senior Developer
- **Type Hints**: 14.9% (Vibecoder) vs. 100% (Senior Developer)
- **Pylint Paradox**: Vibecoder achieved *higher* raw Pylint scores despite lower structural quality

## Dataset Description

### Code Samples (`code_samples/`)

470 Python files organized by problem, with 10 files per problem (5 Vibecoder runs + 5 Senior Developer runs). Each file is a standalone Python solution to a LeetCode problem generated by the respective persona.

### Data Files (`data/`)

| File | Description | Rows |
|------|-------------|------|
| `analysis_results_n5_raw.csv` | Per-file static analysis results for all 470 code files | 470 |
| `analysis_results_n5_median.csv` | Median values per problem–persona pair (representative values) | 94 |
| `intra_persona_variability.csv` | MI variability statistics (median, mean, std, min, max, range) per problem–persona pair | 94 |
| `statistical_results_n5.csv` | Wilcoxon signed-rank tests, BH-adjusted *p*-values, Cohen's *d*, Bootstrap CIs | 11 |
| `summary_table_n5.csv` | Summary statistics formatted for Table 2 in the paper | 11 |

### Analysis Notebooks (`notebooks/`)

| Notebook | Description |
|----------|-------------|
| `notebook1_code_generation.py` | Code generation pipeline using Anthropic API |
| `notebook2_analysis_pipeline.py` | Static analysis pipeline (Radon, Pylint, Bandit) |
| `notebook3_statistical_analysis.py` | Statistical analysis (Wilcoxon, BH correction, Bootstrap CI, subgroup analyses) |

## Reproducing the Experiment

### Prerequisites

- Python 3.12+
- Google Colab (recommended) or local Python environment

### Step 1: Code Generation

```bash
pip install anthropic==0.81.0
```

Set your `ANTHROPIC_API_KEY` environment variable, then run `notebook1_code_generation.py`. This generates 470 code files in `code_samples/`.

> **Note**: The original experiment used `anthropic` library version 0.81.0. Later versions should produce equivalent results, but exact byte-level reproducibility is not guaranteed due to the stochastic nature of LLM generation (temperature = 0.8).

### Step 2: Static Analysis

```bash
pip install radon==6.0.1 pylint==4.0.4 bandit==1.9.3
```

Run `notebook2_analysis_pipeline.py` to compute all static analysis metrics.

### Step 3: Statistical Analysis

```bash
pip install scipy numpy pandas
```

Run `notebook3_statistical_analysis.py` to perform Wilcoxon signed-rank tests, Benjamini–Hochberg correction, Cohen's *d* with Bootstrap confidence intervals, and subgroup analyses.
